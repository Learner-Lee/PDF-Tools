# PDF 对照 · 纯前端版

[← 返回项目主页](../README.md)

与[本地版](../README.md)功能相同，但**没有后端**：

- **PDF 不会上传** —— 解析、分栏、表格识别全在你的浏览器里完成
- **刷新即清空** —— 文件与译文只在内存中，服务器上不留任何痕迹
- **多人同时访问** —— 纯静态站点，每个访客各自独立

代价：不做原版式 PDF 导出（浏览器里没有与 PyMuPDF 对等的实现），只导出 Markdown。

## 部署

```sh
cd web
npm install
npm run build          # 产物在 dist/，约 7 MB
```

把 `dist/` 交给任意静态托管即可 —— Nginx、Vercel、Netlify、GitHub Pages、对象存储都行。
没有后端进程要守护。

部署到子路径（如 `https://example.com/pdf/`）时，先改 `vite.config.js` 里的
`base: "./"` 为 `base: "/pdf/"` 再构建。

本地预览：

```sh
npm run dev            # http://localhost:5274
```

### 难词词库

难词模式需要一份约 4 MB 的词库（gzip 后 1.5 MB），首次访问下载一次后存进
浏览器的 IndexedDB，之后秒开。构建产物里已包含 `public/vocab.json`。

要重新生成（例如更新词表后）：

```sh
python3 scripts/build_web_vocab.py
```

它读取仓库根目录的 `data/vocab.db`，那份由本地版的
`backend/scripts/fetch_wordlists.py` + `build_vocab.py` 生成。

## 翻译服务必须允许跨域

浏览器直接调用你选定的 LLM 服务，所以对方必须返回跨域许可头，否则请求会被浏览器拦下。

**实测结果**（不是推测）：

| 服务 | 浏览器直连 |
|---|---|
| DeepSeek、硅基流动、智谱、OpenRouter、OpenAI | ✅ 可直连 |
| 阿里云百炼（通义千问） | ❌ 不返回跨域头，需要下面的代理 |

设置面板里已经把这一栏标出来了，选服务时能直接看到。

Ollama 需要启动时设 `OLLAMA_ORIGINS=*` 才允许网页调用。

### 转发代理（只在必须时才用）

给百炼这类不支持跨域的服务准备的，约 90 行、零依赖：

```sh
UPSTREAM=https://dashscope.aliyuncs.com/compatible-mode/v1 \
ORIGIN=https://你的站点 \
node proxy/server.mjs                       # 默认监听 8788
```

然后在设置里把 base_url 填成 `https://你的域名/proxy/v1`（或 `http://localhost:8788/v1`）。

它刻意做得很受限：

- **上游地址由服务端配置**，客户端不能指定 —— 否则就成了任人使用的开放代理
- 不存储任何东西：不落盘、不打印请求体、无数据库
- 只放行 `/models` 与 `/chat/completions`
- 密钥由浏览器随请求带来、原样转发，代理自身不持有

用了代理之后，**PDF 仍然不经过服务器**，只有抽取出的文本会经代理转发给 LLM 厂商 ——
而那是翻译本身就绕不开的。

## 数据去哪了

| 数据 | 位置 | 生命周期 |
|---|---|---|
| PDF 文件 | 浏览器内存 | 刷新即消失，从不上传 |
| 译文 | 浏览器内存 | 刷新即消失 |
| 生词本 | 浏览器内存 | 刷新即消失，可导出 CSV / Anki |
| API 密钥与阅读设置 | 本机 localStorage | 保留（否则每次刷新都要重填） |
| 难词词库 | 本机 IndexedDB | 保留（静态资源，不含用户数据） |

## 与本地版的差异

| | 本地版 | 纯前端版 |
|---|---|---|
| 解析 | PyMuPDF | pdf.js（逻辑等价移植） |
| 翻译缓存 | SQLite，跨会话保留 | 内存，刷新即清空 |
| 难词词库 | 39 MB 完整版，40 万词 | 4 MB 精简版，4.4 万词 |
| 原版式 PDF 导出 | ✅ | ❌ 只导出 Markdown |
| 多人使用 | 单机 | ✅ 静态站点，天然支持 |

### 移植中值得一提的几处

pdf.js 只给文本项，**不给"块"**，行聚类与块切分要自己做。由此引出两个本地版没有的问题：

- **必须先分栏再聚行**。双栏页面上左右栏同一高度的文字基线完全相同，
  只按基线聚类会把两栏拼进同一行，得到 "Abstract frame comparison as participation…"。
- **页码正落在栏间空白带上**（实测 x294.9~300.4）。计算空白带时若不排除页眉页脚区，
  一个页码就足以让每一页都判成单栏。

栏检测最终用的判据是「中带覆盖相对两侧栏的比值」而非绝对空白 ——
实测真双栏页此比值为 0~26%，被跨栏宽表主导的页面则到 59%，阈值取 35%。

### 已知限制

- 一条横跨左栏底部与右栏顶部的参考文献未能合并（`Ip-` / `polito`），
  40 条文献里的一处，属跨栏合并约束的保守取舍。
- 扫描件仍需 OCR，未实现，上传时会明确提示。
